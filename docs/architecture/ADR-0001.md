# ADR-0001: Durable local post-meeting pipeline

- **Status:** Proposed
- **Date:** 2026-10-18
- **Scope:** MCU Meeting, standalone repository

## Context

Research into `mt-linux` and `meetink` suggests complementary strengths: recoverable post-processing and native macOS capture, respectively. MCU Meeting must preserve original recording artifacts independently of transcription, diarization, identity resolution, and downstream knowledge ingestion.

## Proposed decision

Use separate recording and processing lifecycles. A session has a stable UUID, capture target bundle ID, timestamps, capture-health events, artifact references, and independently tracked processing stages. Processing failures must not invalidate successfully recorded audio. Audio and structured meeting records are authoritative; rendered Markdown is derived output.

For initial scope, prefer manually initiated application-scoped ScreenCaptureKit capture and a separate microphone track. Keep local inference as the default. External services require explicit approval. Do not silently fall back to display-wide capture when application filtering fails.

## Initial contract

`contracts/session.schema.json` defines version `0.1.0`. The fixture demonstrates a completed capture with pending downstream processing. Artifact paths are relative to a session directory; hashes may remain null until files are finalized.

## Consequences and trade-offs

Independent stage states increase bookkeeping but allow retry and reprocessing without rerecording. Stable artifact references support later provenance and MCU vault ingestion. The contract is deliberately small and will evolve before a stable public release.

## Deferred decisions / validation gates

- Final session persistence mechanism and atomic write strategy.
- Capture health event taxonomy, audio clock alignment, and crash recovery semantics.
- Retry scheduling, stage dependencies, and schema migrations.
- Voiceprint retention and speaker enrollment policy.
- Actual Zoom, Slack, and Teams capture behavior; mic track reliability.
- License verification before direct reuse of third-party source.

## Acceptance gates for this proposal

1. Schema and fixture parse as valid JSON.
2. Fixture validates against Draft 2020-12 schema with format checking.
3. An intentionally invalid state is rejected.
4. README and contract documentation are updated when the schema is promoted.
5. ADR remains **Proposed** until separately reviewed and accepted.
